## Lessons learned
| Issue | Resolution | Applies to |
|---|---|---|
| `modbus-discover` on the whole `/24` hung (Ctrl-C) — it probed ~250 dead addresses. | Point Step 3 only at the hosts Step 2 found with `:502` open (`-iL`), and cap each host (`--host-timeout`/`--max-retries`). Near-instant now. | `recon_scan.py` / any NSE scan |
| A "bare" scan run (no sniffer) produces nmap text but **no pcap** — the deliverable needs the pcap. | Run captures as: `tcpdump` on → run scan → `tcpdump` off. Recon pcap must include `arp` in the filter (Step 1 host discovery is ARP). | all scenario captures |
| `scp` to the repo failed on the accented path (`Área`) + a trailing `\"`. | `cd` into the target folder in PowerShell first, then `scp … .` (copy to `.`). Avoids OpenSSH mangling the non-ASCII path. | moving evidence Kali ↔ repo |
| **Both FireAlarm ESP32s (`.12`/`.22`) kept dropping Wi-Fi.** First hypothesis was brownout (MQ-9 heater load); **Luis confirmed on the bench the real cause is poor Wi-Fi signal in the room** (partially mitigated). | Signal fixes (repeater/AP closer, reposition antenna, clean channel, `WiFi.setSleep(false)`); node must be up to demo Scenario 4. | FireAlarm nodes |
