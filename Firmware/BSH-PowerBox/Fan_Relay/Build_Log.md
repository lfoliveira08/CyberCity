## Lessons Learned
- **A bench finding is tied to a specific physical component, not to "the fan channel" in the abstract.** Swapping the relay module invalidated the Sep 30 finding even though the GPIO pin, firmware logic, and Modbus register were unchanged. The new 1-channel board happened to need the same flag value as the old module, but that was independently verified, not inherited.
- **Two channels on the same physical relay module are not guaranteed to share a polarity** — confirm each channel independently rather than copying the first channel's `RELAY_ACTIVE_LOW` value to the second.
- **"It works" isn't the same as "it works correctly."** Fan toggling on/off looked fine and went unquestioned for a full day while lights (same circuit pattern, different pin) was being debugged — but fan was inverted the entire time. Worth deliberately re-checking a channel that "already works" once a sibling channel turns out to have a subtle bug, instead of assuming it's fine by comparison.
- **Wokwi's relay polarity is not the same as most real relay modules — except when it is.** `wokwi-relay-module` energizes on HIGH in this simulator; the "typically active-LOW" real-hardware assumption in `Wiring.md` turned out to be wrong for *this* module too (also active-HIGH), but for an unrelated reason — coincidence, not the sim carrying over. Still check every module fresh; don't use this result to assume active-HIGH is now the safe default either.
- See `../Lights_Relay/Build_Log.md` for the full GPIO-strapping-pin red herring and the `ButtonState`-struct Arduino/Wokwi compile bug — both were found via this channel's comparison against lights, and both got fixed in this sketch too.

## Troubleshooting Tips
- LED or relay's onboard LED1 lit when it should be off (or vice versa): check `RELAY_FAN_ACTIVE_LOW` (real firmware, its own flag as of Sep 30, 2026) or `RELAY_LIGHTS_ACTIVE_LOW`/`RELAY_FAN_ACTIVE_LOW` (Wokwi sketch) match your actual module/simulator — don't assume one matches the other, and don't assume this channel is fine just because it seems to toggle.
- Motor spins when the Serial log says OFF (or sits still when it says ON): flip `RELAY_FAN_ACTIVE_LOW` and re-flash — expected module-to-module variation, not a wiring mistake. **Confirmed value for this node's new 1-channel board (Oct 5, 2026): `RELAY_FAN_ACTIVE_LOW = false`.**
- Zero Serial output at all when pressing the fan button or sending `f`: before suspecting wiring or GPIO strapping pins, confirm the sketch actually flashed on the board is the one you think it is — this exact symptom on Oct 5, 2026 turned out to be an old lights-only sketch still running, not a hardware fault.
